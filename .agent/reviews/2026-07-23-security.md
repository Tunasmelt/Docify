Scope: `apps/api/routes/`, `apps/api/services/`, `apps/api/db/`, `apps/api/models/`, `apps/api/middleware/`, `apps/api/migrations/`.

## Findings

### [CRITICAL] Known CVEs exist in the current backend dependency set, including direct ingest-path packages

Must fix now before exposing the app to untrusted uploads.

`pip-audit` reported 45 vulnerability records across 5 packages in the current installed backend environment:

- `docling==2.87.0`: multiple `PYSEC-2026-2142` through `PYSEC-2026-2146`, fixed in `2.91.0` / `2.94.0`.
- `pillow==11.3.0`: multiple `PYSEC-2026-*` records, fixed across `12.1.1`, `12.2.0`, and `12.3.0`.
- `starlette==0.46.2`: multiple `PYSEC-2026-*` records, fixed across `0.47.2`, `0.49.1`, `1.0.1`, `1.1.0`, `1.3.0`, and `1.3.1`.
- `langsmith==0.8.5`: `GHSA-f4xh-w4cj-qxq8`, fixed in `0.8.18`.
- `pytest==8.4.2`: `PYSEC-2026-1845`, fixed in `9.0.3` (dev-only, lower urgency).

The first three matter for this project regardless of portfolio scale: FEAT-007 accepts user-controlled PDFs, routes them through Docling/Pillow, and serves through FastAPI/Starlette. This is exactly the "looks fine, isn't" class for a parser-heavy ingest service.

### [WARNING] Raw rejected `storage_path` values are logged on traversal attempts

Fine to defer for local-only development, but should be tightened before public demo traffic if logs are hosted externally.

`post_ingest()` logs the full attacker-supplied storage path on validation failure (`apps/api/routes/ingest.py:148`). The pipeline path also logs the full exception and traceback for validation failures (`apps/api/routes/ingest.py:259`), and the exception text includes the supplied `storage_path`.

The response remains generic (`FORBIDDEN`, no detailed oracle), and my log run did not show JWTs, API keys, service-role tokens, or document bytes. However, the log line can include another user's UUID embedded in a traversal attempt, percent-encoded probes, and arbitrary filename text. Since filenames are user-controlled metadata, avoid logging the raw path in production; log document id/user id plus a coarse validation reason instead.

Evidence from targeted log run:
- Bad JWT: no token logged.
- Unsupported MIME: no body/log leak observed.
- Embedder failure: stack trace logged, no chunk/document content.
- Traversal route and pipeline failures: full crafted `storage_path` logged.

### [INFO] Storage path traversal fix holds under additional variants

No new vulnerability found.

`validate_storage_path()` is enforced at both authorization boundaries:

- synchronous route check before document creation (`apps/api/routes/ingest.py:146`);
- background/internal pipeline check before service-role client creation, download, parse, chunk, embed, or DB writes (`apps/api/routes/ingest.py:216`).

The returned value is the same validated string, and downstream download derives `in_bucket_path` from that exact value (`storage_path.removeprefix("uploads/")` at `apps/api/routes/ingest.py:229`). There is no later decode or alternate value used for Storage access.

The final whitelist is applied to the full remainder after `uploads/{user_id}/`, not only to one segment. It rejected:

- `%2E%2E%2F`, `%2e%2e%2f`, `..%2f`;
- double-encoded `%252e%252e%252f`;
- overlong UTF-8 byte spellings like `%c0%ae%c0%ae%c0%af`;
- `%u002e%u002e%u2215`;
- Unicode slash lookalikes `U+2215` and `U+FF0F`;
- raw and encoded null bytes;
- subdirectories;
- decomposed Unicode in filenames;
- encoded dot in `legit%2epdf`.

`LEGIT.PDF` was accepted, which is consistent with `[A-Za-z0-9._-]+`.

### [INFO] Cross-cutting auth is currently closed except `/health`

No issue found.

`main.py` installs `JWTAuthMiddleware` globally before including routers. Current routes are `/health` and `/ingest`, plus FastAPI's generated docs/OpenAPI routes. The middleware exempts only `/health` (`apps/api/middleware/auth.py:11`, `apps/api/middleware/auth.py:45`), so `/ingest`, `/docs`, `/redoc`, and `/openapi.json` all pass through JWT auth in this app.

No alternate unauthenticated internal route reaches `run_ingest_pipeline()`. Direct Python calls can bypass HTTP middleware, but the function re-validates `storage_path` before service-role construction or Storage access.

### [INFO] SQL/query injection surface is currently parameterized or query-builder based

No issue found in app code.

The API code uses Supabase's query builder for all user-controlled fields:

- document insert: `filename`, `storage_path`, `mime_type`, `size_bytes`, `user_id` via `.insert({...})`;
- status updates/deletes: `.eq("id", document_id)` / `.eq("document_id", document_id)`;
- chunk insert: one `.insert(rows)` call.

No app-code raw SQL, string-built SQL, or `.rpc()` path exists in `routes/`, `services/`, `db/`, `models/`, or `middleware/`. Raw `psycopg` queries appear only in tests and use parameter placeholders.

### [INFO] Service-role client is not exposed in responses or normal unauthenticated code paths

No issue found.

`get_service_role_client()` reads `SUPABASE_SERVICE_ROLE_KEY` only inside `db/client.py`. In HTTP flow, JWT middleware must attach `request.state.user_id` before `/ingest` can run. `post_ingest()` validates ownership before constructing the service-role client (`apps/api/routes/ingest.py:146` then `apps/api/routes/ingest.py:162`). `run_ingest_pipeline()` also validates before constructing its own client (`apps/api/routes/ingest.py:216` then `apps/api/routes/ingest.py:218`).

No response payload includes the service-role key or client object. Grep found no logger usage that prints env vars or client internals.

### [INFO] Rate limiting remains absent and correctly scoped to Phase 5

No new gap introduced.

There is no app-level rate limiting middleware or per-route limiter in `apps/api`. `.agent/SCOPE.md` still explicitly puts rate limiting for `/ingest` and `/query` in Phase 5. This is acceptable for local portfolio development, but before public deployment it should be added because `/ingest` can trigger expensive Docling CPU work and Voyage calls.

### [INFO] JWT/auth checks from prior passes still hold

No regression found in current tree.

`jwt.decode()` pins `algorithms=["ES256"]`, validates issuer and audience, and requires `exp` (`apps/api/middleware/auth.py:56`). Unknown/malformed tokens return the same generic `UNAUTHORIZED` envelope. Targeted auth tests passed.
