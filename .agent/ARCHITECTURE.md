# Architecture

Single source of truth for how the system is built. Agents must read the relevant section before touching a module. History of how this design evolved lives in `CHANGELOG.md` and `.agent/MEMORY.md §Decision log`, not here — this file describes the system as it is now.

---

## Overview

Multi-tenant SaaS web app: users upload documents (PDF, DOCX, PPTX, HTML), ask natural-language questions, and receive answers with verified inline citations that link back to the exact source page, slide, or element.

The retrieval strategy is **layout-aware structured parsing**: a heuristic parser built on pdfplumber / python-docx / python-pptx / selectolax extracts typed elements (text, tables, figures, headings) preserving reading order and element relationships. Chunks are embedded with a unified multimodal encoder (Voyage, with a Gemini fallback), answers are generated by Gemini 3.6 Flash, and every citation is re-checked by Gemini 3.5 Flash-Lite before it is returned.

### Multi-tenancy — two enforcement paths

Every user-owned row carries a `user_id`. How that is enforced depends on who is querying:

| Caller | Client | Enforcement |
|---|---|---|
| Browser → Supabase directly (auth, storage, avatar) | anon key + user JWT | **Postgres RLS** (`auth.uid() = user_id`) and Storage policies — the database refuses cross-tenant rows |
| Browser → FastAPI → Supabase (documents, chunks, conversations, query, export, account) | **service-role key** | **Application code.** The service role bypasses RLS entirely, so every query FastAPI makes *must* filter by the JWT-derived `user_id` (`WHERE user_id = $auth`, `p_user_id` in every RPC). RLS is not a backstop on this path. |

RLS is therefore the defense for the direct-to-Supabase path and for any future anon-key access; the explicit `user_id` filter is the *only* defense on the FastAPI path. Any new FastAPI query that omits it is a cross-tenant leak. See SCHEMA.md §Row-Level Security and STANDARDS.md.

| Generation | Gemini | 3.6 Flash | All LLM calls consolidated on one provider |
| Verification | Gemini | 3.5 Flash-Lite | Cheap, fast LLM-as-judge for citation grounding |
| Database | Postgres (Supabase) | 15+ | pgvector + FTS + RLS in one system |
| Vector search | pgvector | 0.7+ | HNSW, same DB as metadata |
| Auth | Supabase Auth | — | JWT (ES256 via JWKS), email/password + Google OAuth |
| File storage | Supabase Storage | — | Path-scoped buckets with RLS |
| Rate limiting | slowapi + Postgres `usage_counters` | — | Per-minute in memory, daily in Postgres (survives Render spin-down) |
| Frontend deploy | Vercel | Hobby | Git-linked, auto-deploy on push |
| Backend deploy | Render | Free tier, **Docker runtime** | See constraint below |

**The backend must deploy via Docker on Render, not the native Python runtime.** Tesseract (OCR tier 3) is a system binary (`tesseract-ocr`); `pytesseract` is only a wrapper around it. Render's native runtime blocks `apt-get`, so only a container can provide it. `GET /health` returns the running commit (`RENDER_GIT_COMMIT`) — use it to confirm a fix is actually deployed.

## Request flows

### Ingest flow
```
1. User selects a file (PDF/DOCX/PPTX/HTML) on the Documents page
2. Browser uploads it directly to Supabase Storage: uploads/{user_id}/{uuid}.{ext}
3. Browser POSTs to FastAPI POST /ingest { storage_path, filename, mime_type, size_bytes }
   with Bearer <supabase_jwt>. JWTAuthMiddleware verifies the JWT and attaches user_id.
   FastAPI validates storage_path is under the caller's own uploads/{user_id}/ prefix.
4. FastAPI creates the documents row (status='uploaded'), returns 202, and continues in a
   BackgroundTask:
   a. Downloads the file from Storage (service-role client)
   b. Parses → typed elements (text, tables, figures, headings) with page/slide + bbox
      (status='parsing'); low-yield PDF pages go through the OCR fallback chain
   c. Uploads cropped figures to Storage: figures/{user_id}/{document_id}/{figure}.png
   d. Chunks elements (services/chunker.py — see Locked decisions)
   e. Embeds chunks with Voyage; a batch whose Voyage retries are exhausted falls back to
      Gemini embedding-2. Both honor the provider's server-supplied retry delay.
      chunks.embedding_provider records which provider produced each vector (status='embedded')
   f. Bulk-inserts chunk rows with user_id, then sets status='ready'
   Any failure → status='failed' with documents.error set, no partial chunks left behind.
5. Frontend polls GET /documents for status transitions. A document stuck in
   parsing/embedded for 30+ minutes (e.g. the process was killed) is reaped to 'failed'
   on the next GET /documents; POST /reindex/{id} re-runs the pipeline.
```

### Query flow
```
1. User submits a question on the chat page
2. Browser POSTs to FastAPI POST /query or POST /query/stream { question, document_ids,
   conversation_id?, k?, rerank? } with Bearer <supabase_jwt>
3. FastAPI (services/retriever.py):
   a. Finds which embedding provider(s) have chunks in the document_ids scope (almost
      always just "voyage")
   b. Embeds the question once PER provider present and runs that provider's own vector
      search (filtered by user_id, document_ids, embedding_provider). Vectors from
      different providers are never compared — see MEMORY.md §Anti-patterns 2026-07-31
   c. Runs one Postgres FTS search in parallel
   d. Reciprocal Rank Fusion merges all lists purely by rank → top-k
   e. If rerank=true, Voyage rerank-2.5 reorders the candidate pool; any failure falls
      back to RRF's order
   f. Builds the prompt: system instruction + numbered chunks [1]..[k] + up to the last 5
      conversation turns + the question
   g. Calls Gemini 3.6 Flash; the answer contains inline [N] markers
   h. Maps markers back to chunk IDs, recovering claim spans (sentence → wider spans)
   i. Runs the verify flow on each cited claim
   j. Persists conversation + messages + citations atomically (create_query_turn RPC)
4. Returns { answer, citations: [...], metadata }, or streams the same content as SSE
   events (with 12s keepalive frames) via /query/stream. A client disconnect or user
   "stop" aborts the turn and nothing is persisted.
```

### Verify flow (internal — called from query, not a public endpoint)
```
For each (claim_span, cited_chunk_id) pair:
1. Fetch the chunk content
2. Call Gemini 3.5 Flash-Lite: given source + claim → supported | partial | unsupported,
   plus a supporting quote. A quote that is not actually in the source is treated as
   unsupported.
3. If the Gemini call errors, times out, or returns a malformed response, the verdict is
   `unverified` — an infrastructure failure, never conflated with `unsupported`
4. Treatment:
   - supported / partial / unverified: returned to the client, each with distinct chip
     styling (solid / dotted-amber / dashed-muted)
   - unsupported: dropped from the response and its [N] marker stripped from the answer
     text (_strip_dropped_markers, routes/query.py)
5. All verdicts, including unsupported, are persisted to `citations` for audit. The only
   place unsupported citations surface is GET /export/conversations.
```

## Patterns

- **Direct browser-to-FastAPI calls, no proxy layer.** `apiFetch()` calls FastAPI from the browser with the Supabase JWT. All business logic lives in FastAPI; the frontend never talks to Voyage/Gemini/the parser.
- **Service-role client with explicit tenant scoping.** FastAPI uses the service-role key, which bypasses RLS. Every INSERT includes the JWT-derived `user_id`, and every SELECT/UPDATE/DELETE/RPC filters on it. This filter is the tenant boundary for the FastAPI path — not defense in depth.
- **Pydantic contract mirroring.** Models in `apps/api/models/` are the source; matching TS types in `apps/web/lib/types/` are hand-mirrored. API_CONTRACT.md is the specification both sides read.
- **Status-transition documents.** `documents.status` moves uploaded → parsing → embedded → ready | failed. The frontend polls `GET /documents`; it never assumes ready.
- **Storage before DB on delete.** `DELETE /documents/{id}` and `DELETE /account` remove Storage objects first and DB rows last, so a mid-sequence failure leaves the resource intact and the call retry-safe (Storage objects do not cascade on user deletion).
- **Atomic multi-table writes via RPC.** A query turn (conversation + 2 messages + N citations) is written by one plpgsql function, `create_query_turn`, because PostgREST has no client-side transaction.

## Locked decisions

Changing any of these requires human confirmation.

- [x] **Layout-aware parsing is the v1 strategy**, implemented with a heuristic pdfplumber / python-docx / python-pptx / selectolax parser (FEAT-027 replaced Docling, whose memory use OOM-crashed `/ingest` on Render). Other strategies deferred to a v2 strategy selector.
- [x] **Multi-tenant from day one.** RLS on every user-owned table for direct client access; explicit `user_id` scoping on every service-role query in FastAPI (see Overview).
- [x] **Monorepo.** One repo, `apps/web` + `apps/api`.
- [x] **Vercel + Render, no Kubernetes.** Free tiers, git-linked deploys.
- [x] **pgvector, not a dedicated vector DB.** One Postgres serves metadata + vectors + FTS.
- [x] **Voyage multimodal-3.5 for embeddings**, with a per-chunk Gemini embedding-2 fallback. CLIP-style models rejected (modality gap).
- [x] **Gemini for generation + verification.** 3.6 Flash + 3.5 Flash-Lite — one LLM provider.
- [x] **Single-agent workflow.** The original four-agent lane model (claude-code / claude-design / gemini / codex) was retired in practice: gemini was dropped 2026-07-24 and every commit since has been made by claude-code. AGENT.md describes the current workflow; external review passes (e.g. Codex reviews under `.agent/reviews/`) are still welcome as one-off audits.
- [x] **Chunking: element-boundary-respecting, not fixed-token.** `services/chunker.py` groups adjacent text/heading/list elements toward `TOKEN_BUDGET` (~500 tokens), keeps tables and figures as their own chunks, and only splits an element larger than `MAX_CHUNK_TOKENS` (4000) — by table row or by paragraph/sentence, never mid-row.
- [x] **Rerank: opt-in, default off.** RRF alone put the expected chunk in the top 5 on 4/4 fixture questions; rerank added ~380ms with no measured gain. Exposed as a user preference.
- [x] **No query-time query rewriting.** Prior turns go into the generation prompt only; retrieval uses the raw current question. A follow-up with no overlap with its target content may retrieve poorly — a known, accepted limitation.
- [x] **Document status: polling, not Supabase realtime.**

## Conventions

Full standards in STANDARDS.md. Quick reference:

- **Files & folders:** `kebab-case` files, `PascalCase` React components, `snake_case` Python
- **API paths:** `/ingest`, `/query` — no trailing slash, no versioning until needed
- **Env vars:** `SCREAMING_SNAKE`, `.env.example` at each app root, never commit real values
- **Errors:** FastAPI returns `{ error: { code, message, detail } }` with an HTTP status. Each protected route has an error boundary
- **Commit format:** `<type>(<scope>): <summary> [<agent-tag>]` — e.g. `feat(api): add /ingest endpoint [claude-code]`
- **Branch naming:** `feat/FEAT-001-ingest-endpoint`, `fix/parse-error-empty-pdf`, `chore/bump-pdfplumber`
